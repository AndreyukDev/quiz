# quiz — тренажёр теории для поддержания senior-уровня

## Зачем
Хозяин — Java-разработчик уровня senior. Цель — **держать теорию в тонусе без чтения километров текста**: раз в неделю 10–15 минут прощёлкать карточки на телефоне и прочитать короткие разборы. Это не учебник и не курс с нуля: вопросы — уровня собеседования senior, разборы — короткие.

Принципы, ради которых всё делается:
- **Вспоминание, а не перечитывание** (testing effect): сначала ответить самому, потом увидеть разбор.
- **Интервальное повторение** (Лейтнер): ошибки возвращаются чаще, уверенное — реже.
- **Не только узнавание.** Выбор из 4 тренирует узнавание, а на собеседовании нужно объяснить самому. Поэтому есть карточки «объясни сам».
- **Неверный уверенный ответ хуже, чем никакого.** Каждый факт сверен с первоисточником, у каждого ответа ссылка.

## Формат
- **Одна страница `index.html`**, без зависимостей и CDN, работает офлайн. Свой CSS (~5–8 КБ): системный шрифт, крупные кнопки под палец, автоматическая тёмная и светлая тема (`prefers-color-scheme`), карточка по центру, плавный переход, зелёная или красная подсветка ответа, прогресс-бар. Без Bootstrap: тяжёлый и узнаваемый.
- **PWA**: `manifest.webmanifest` + service worker → «добавить на главный экран», работает без сети.
- **Хостинг**: GitHub Pages (репа `quiz`). Публичная или приватная — решает хозяин; Pages из приватной репы — только на платном плане, и сайт всё равно открыт по ссылке. Запасной вариант — приватная репа + Cloudflare Pages.
- Мобильный в первую очередь; на десктопе — та же колонка по центру.

## Виды карточек
| Вид | `type` | Как работает | Доля |
|---|---|---|---|
| Выбор из 4 | `mcq` | тап → верно/неверно → разбор | основная |
| Что напечатает код | `output` | сниппет + варианты вывода (или «не скомпилируется», «исключение …») | много в core и concurrency |
| Верно / неверно | `tf` | утверждение-ловушка | немного |
| Объясни сам | `recall` | вопрос → «показать ответ» → самооценка «знал / частично / не знал» | ~1 из 5 |

Разбор после ответа: 2–5 строк, по делу, почему верный верен и чем ловят остальные варианты. Ссылки на источники — внизу разбора.

## Повторение и прогресс
- Система Лейтнера, 5 коробок. Неверный ответ или «не знал» → коробка 1; верный → +1. Интервалы примерно: 1 → каждая сессия, 2 → через 3 дня, 3 → неделя, 4 → 2 недели, 5 → месяц.
- Сессия: выбрать блок или «микс недели» (из всех блоков: сначала просроченные, потом новые), 10–15 карточек (настраивается).
- Прогресс — в `localStorage` по `id` вопроса. **Экспорт и импорт одной строкой** (base64 JSON) — `localStorage` на мобиле иногда очищается.
- Экран статистики: по блокам — сколько выучено (коробки 4–5), где ошибки, когда следующее повторение.
- Перемешивать варианты ответа при каждом показе.

## Данные
- Вопросы — в `data/<block>.json`, по файлу на блок. Блоки **не только про Java**: тематика расширяемая (SQL, Kotlin, Kafka, Docker/K8s, system design…). Новый блок = новый файл + строка в `data/blocks.json` (id, название, иконка-эмодзи, порядок).
- Сборка — скрипт (Python stdlib или Node без зависимостей) `build`: валидирует все JSON по схеме и вшивает их в `dist/index.html`. Pages публикует `dist/` (или корень — как проще).
- Схема вопроса (уточнить при реализации):
  ```json
  {
    "id": "java-core-hashcode-contract-01",
    "block": "java-core",
    "topic": "equals/hashCode",
    "type": "mcq",
    "level": "senior",
    "question": "…",
    "code": {"lang": "java", "text": "…"},
    "options": ["…", "…", "…", "…"],
    "answer": 1,
    "explanation": "…",
    "sources": [{"title": "JLS §…", "url": "https://…"}],
    "java_version": "21",
    "verified": {"by": "reviewer", "at": "YYYY-MM-DD"}
  }
  ```
  `id` стабильный: по нему хранится прогресс, переименовывать нельзя. У `recall` нет `options`/`answer`, есть `answer_text`.
- Валидатор: уникальные `id`; у `mcq`/`output` ровно один верный; есть `explanation` и хотя бы один `sources`; `code.lang` — из поддерживаемых.

## Подсветка кода
Своя, без библиотек, для нескольких языков: java, kotlin, sql, js/ts, yaml, bash, json. На язык — небольшой набор регулярок: ключевые слова, строки, комментарии, числа, аннотации. Цвета — из темы (светлая и тёмная). Моноширинный шрифт, горизонтальная прокрутка длинных строк, без переноса.

## Контент: правила
- **Формулировки свои.** Чужие банки вопросов дословно не копировать (лицензии и ошибки); сайты с вопросами можно смотреть только как подсказку тем.
- **Факты — по первоисточникам**: JLS, JVMS, JEP, javadoc и документация OpenJDK, Spring docs, PostgreSQL docs, Kafka docs. Вторичные (Baeldung, статьи авторов JDK) — допустимы как дополнительная ссылка, не единственная.
- Целевая версия Java — **21 (LTS)**; где поведение отличается в 25 — отметить в разборе.
- Уровень — senior: ловушки, граничные случаи, «почему так устроено», компромиссы. Без вопросов уровня «что такое класс».
- Сниппеты «что напечатает» — **проверять запуском** (`java File.java` на JDK 21), а не в уме. Если JDK нет — сказать хозяину, а не угадывать.
- **Проверка вторым агентом-противником** для каждого блока: ищет фактические ошибки, двусмысленные формулировки, второй верный вариант, устаревшее. Находки — исправить или выбросить вопрос; в вопросе — отметка `verified`.
- Блок — 30–50 вопросов; темы внутри блока покрыть равномерно.

## Блоки (план)
1. **java-core** — коллекции (внутренности HashMap, ConcurrentModification, неизменяемые), equals/hashCode/compareTo, generics (стирание, wildcards, PECS), String и пул, records, sealed, pattern matching, исключения, Optional, stream API и его ловушки — **первый, на пробу**
2. concurrency — JMM, happens-before, volatile, synchronized/Lock, CAS и atomics, executors, CompletableFuture, virtual threads
3. jvm-gc — память, G1/ZGC/Parallel, JIT, флаги, JFR, async-profiler, утечки
4. spring — бины и прокси, @Transactional и его ловушки, AOP, Boot
5. persistence — JPA/Hibernate, транзакции и изоляция, блокировки, индексы PostgreSQL
6. system-design — кэши, консистентность, идемпотентность, outbox, saga, rate limiting, шардирование
7. kafka — семантика доставки, порядок, ребалансы, consumer groups
8. microservices — retry, circuit breaker, таймауты, наблюдаемость
9. java-new — что нового 17→25 по JEP
10. по желанию: testing, security (OAuth2/JWT), sql, algorithms

### Статус и пробелы ядра (2026-11-09)
- **java-core — готов**: 50 вопросов, по 3–5 на тему из п. 1, сниппеты прогнаны на JDK 21, агент-противник пройден. Перекос: 25 из 50 — «что напечатает»; если мешает — часть перевести в mcq.
- **Сейчас: хозяин обкатывает на телефоне** (шаг 3 порядка работы). Новые блоки — после его правок формата.
- 50 вопросов ядро не закрывают. Решено делить ядро на блоки, а не раздувать java-core. Следующие (вставить в план перед concurrency):
  - **java-lang** (~40): кеш `Integer` (127/128), NPE автораспаковки в тернарнике, выбор перегрузки (widening → boxing → varargs), порядок инициализации и вызов переопределённого метода из конструктора, `byte b += 1` vs `b = b + 1`, `0.1+0.2`, `NaN`, `-0.0`; default-методы и «ромб», правила переопределения (ковариантный возврат, throws, видимость), скрытие static, inner-классы и захват `this`; enum (синглтон, `EnumMap`, тела констант); лямбды: effectively final, bound/unbound ссылки, `obj::m` вычисляет получатель сразу.
  - **java-collections** (~35): `LinkedHashMap` access-order/LRU, `TreeMap`/`NavigableMap`, `PriorityQueue` (итератор не по порядку), `ArrayDeque`, `WeakHashMap`/`IdentityHashMap`, рандомизированный порядок `Set.of`/`Map.of`, `Comparator.comparing`/`nullsFirst`.
  - **Stream API и generics глубже** (в эти блоки или отдельный `java-functional`): `groupingBy`/`partitioningBy` + downstream, `flatMap`/`mapMulti`, `reduce` и identity, `teeing`, примитивные стримы; Gatherers (JEP 485, финал в 24 — отметить для 25); bridge-методы, `<T extends Comparable<? super T>>`, `@SafeVarargs`, capture helper; строки: суррогатные пары (`length()` vs `codePoints()`), text blocks.
- Тяжёлую генерацию блоков запускать из `claude` CLI по подписке, а не через agent.py (API).

## Порядок работы
1. Каркас: `index.html` (UI, Лейтнер, `localStorage`, экспорт/импорт, статистика, подсветка), PWA, схема и валидатор, скрипт сборки. 3–4 тестовых вопроса всех типов.
2. Блок `java-core`: темы → вопросы → прогон сниппетов → проверка агентом-противником → правки.
3. Хозяин неделю гоняет на телефоне → правки формата.
4. Остальные блоки — по одному, тем же порядком.

## Как устроено (сделано)
- `src/` — `index.html`, `style.css`, `app.js`, `sw.js`, `manifest.webmanifest`; сборка вшивает CSS, JS и данные в `dist/index.html`, генерирует иконки.
- `python3 scripts/build.py [--check]` — валидация `data/*.json` по схеме и сборка `dist/`.
- `python3 scripts/run_snippets.py [блок] [--id ID]` — прогон java-сниппетов с полем `expect` (`stdout` / `exception` / `compile_error`) на установленном JDK. Сниппет без `static void main` — тело `main` со стандартными импортами.
- `python3 scripts/check_links.py [блок]` — ссылки из `sources` и якоря на страницах.
- Схема сверх описанной выше: `tf` → `answer: true|false`; `output` → обязательный `expect`; `code.text` — строка или массив строк; `level` — `middle`/`senior`.
- Деплой: `.github/workflows/pages.yml` собирает и публикует `dist/` (в настройках Pages выбрать Source: GitHub Actions).

## Окружение
- Запускать `claude` CLI в этой папке (по подписке). Это **не** проект фабрики (`factory`): гейтов фабрики здесь нет.
- Секреты не нужны. Токены GitHub — только у хозяина (`gh auth`), коммиты и push — по его просьбе.
- Скрипты для хозяина — файлами в `scripts/`, без вставок Python в чат.
