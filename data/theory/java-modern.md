## Главное в пяти правилах
- **Состояние записи — ровно её компоненты.** `equals`, `hashCode`, `toString` и аксессоры выводятся из них; на этом же держатся record patterns и сериализация. Неизменяемость поверхностная: массив сравнивается по ссылке, список можно поменять снаружи.
- **Компактный конструктор работает с параметрами, а не с полями.** Проверяет и нормализует (`name = name.strip()`), поля присваиваются автоматически после тела.
- **Sealed даёт компилятору полный список наследников.** Switch по такому типу исчерпывающий без `default`, и новый наследник ломает компиляцию каждого switch — ни один случай не забудется.
- **Switch с паттернами: `null` и порядок меток.** Без `case null` — NPE, `default` его не ловит. Метки идут от частного к общему: недостижимая метка — ошибка компиляции.
- **Переменная паттерна видна только там, где сопоставление точно удалось** (flow scoping): справа от `&&`, в `then`, после `if (!(o instanceof T t)) return;`.

## Records
- Запись неявно `final`, прямой суперкласс — всегда `java.lang.Record`; `extends` запрещён, интерфейсы — можно.
- Поля экземпляра сверх компонентов запрещены (`field declaration must be static`); статические поля и любые методы — можно.
- `equals` сравнивает ссылочные компоненты через `Objects.equals`: у `record Data(int[] v)` две записи с одинаковым содержимым не равны. Лечится `List` вместо массива или переопределением `equals`/`hashCode`/`toString`.
- Аксессор отдаёт ссылку на тот же объект. Глубокая неизменяемость — защитная копия в конструкторе:
```java
record Tags(List<String> tags) {
    Tags { tags = List.copyOf(tags); }   // отвязка от списка вызывающего, NPE на null
}
```
- Аксессор можно переопределить, но он обязан быть `public` и с тем же типом.
- Вложенная запись неявно `static`.

## Конструкторы записи
```java
record Range(int lo, int hi) {
    Range {                                 // компактный канонический
        if (lo > hi) throw new IllegalArgumentException(lo + " > " + hi);
    }
    Range(int x) { this(x, x); }            // неканонический — только через this(...)
}
```
- В компактном конструкторе `this.lo = …` — ошибка: поле присвоит компилятор после тела.
- Канонический конструктор не может вызывать `this(...)`; неканонический обязан начинаться с него.
- При десериализации запись создаётся через канонический конструктор — проверки инвариантов срабатывают и там (у обычного класса — нет).

## Record против Lombok @Value
- Язык гарантирует «прозрачный носитель»: деконструкция в паттернах, сериализация через конструктор, `Class.getRecordComponents()`.
- Цена: нет скрытых, ленивых или вычисляемых полей экземпляра; не годится в JPA-сущности (нужны не-`final` класс, конструктор без аргументов, изменяемые поля).

## Sealed
- `sealed interface Shape permits Circle, Square {}` — реализовать могут только перечисленные.
- Каждый разрешённый наследник объявляет себя `final`, `sealed` или `non-sealed` (снова открывает ветку). Запись и enum уже неявно `final`.
- Где лежат наследники: в именованном модуле — в любом пакете того же модуля, в безымянном — в том же пакете. `permits` можно опустить, если все наследники в том же файле.
- Зачем, если есть `final` и package-private конструктор: те закрывают иерархию, но не сообщают компилятору список наследников. Sealed + records = алгебраические типы данных (sum + product).

## Исчерпывающий switch
```java
double area(Shape s) {
    return switch (s) {
        case Circle c -> Math.PI * c.r() * c.r();
        case Square q -> q.side() * q.side();
    };   // default не нужен — и лучше без него
}
```
- С `default` новый наследник молча уйдёт в ветку по умолчанию; без него — ошибка компиляции.
- Иерархию поменяли, а switch не перекомпилировали — в рантайме `MatchException` (javac вставляет синтетический `default`).
- Switch-**выражение** обязано быть исчерпывающим всегда. Switch-**оператор** — если в нём есть паттерны или `case null` либо тип селектора не из старых (не примитив, обёртка, `String` или enum); старый оператор по enum без паттернов — нет.

## Pattern matching в switch
- `null`-селектор без `case null` → `NullPointerException`, даже при `default`. Обработать: `case null ->` или `case null, default ->`.
- Доминирование: `case Integer i` перед `case Integer i when i > 10` или `case CharSequence c` перед `case String s` — `this case label is dominated by a preceding case label`. Паттерн после `default` — тоже ошибка.
- Guard: `case Integer i when i > 10 ->` — проверяется после совпадения типа.
- Провал (`:` без `break`) в метку с паттерном запрещён: `illegal fall-through to a pattern`.

## Record patterns
```java
if (o instanceof Line(Point(var x1, var y1), Point p2) && x1 < p2.x()) { ... }

case Neg(Num(var v)) -> -v;      // сначала узкий
case Neg(var inner)  -> -eval(inner);
```
- Вкладываются и смешиваются с `var` и type patterns (Java 21, JEP 440).
- Record pattern не совпадает с `null`: ни на верхнем уровне, ни во вложенном компоненте. А вложенный `var p` или `Point p` с типом самого компонента совпадает и с `null` — `p2` может оказаться `null`.

## Flow scoping
- `if (!(o instanceof String s)) return;` — дальше `s` доступна.
- `o instanceof String s || s.isEmpty()` — ошибка: справа сопоставление как раз не удалось. `&&` — можно.
- `if (!(o instanceof String s)) { s… }` — ошибка: внутри `s` не присвоена.

## После Java 21
- `_` — безымянные переменные и паттерны (`case Point(var x, _)`): в 21 preview, финал в 22 (JEP 456).
- Примитивные типы в паттернах (`case int i when i > 5`): в 21 нет; preview в 23–25 (JEP 455, 488, 507).
