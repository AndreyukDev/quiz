## Главное в трёх правилах
- **Каждая константа существует в одном экземпляре — это гарантирует JVM.** Отсюда сравнение через `==`, синглтон на enum и `EnumMap` без хеширования.
- **`ordinal()` и порядок объявления — не идентификатор.** Вставка или перестановка констант сдвигает номера; хранить и передавать наружу нужно имя или явный код.
- **`valueOf` строгий**: точное имя с учётом регистра, иначе `IllegalArgumentException`, на `null` — NPE. Внешний ввод разбирают своим поиском.

## Устройство
- Enum неявно `final` (если ни у одной константы нет тела) и наследует `java.lang.Enum`; от другого класса наследоваться не может, интерфейсы реализует.
- Конструктор всегда `private`, `new` для enum запрещён. Рефлексия тоже не создаст: `Cannot reflectively create enum objects`.
- В конструкторе нельзя обращаться к не-константным статическим полям своего enum — ошибка компиляции: константы создаются раньше остальной статики. Константные переменные (`static final int K = 5`) — можно.
- `equals`, `hashCode`, `compareTo`, `name()` — `final`. `toString()` переопределять можно, поэтому для хранения брать `name()`.
- `compareTo` сравнивает по порядку объявления.
- `values()` каждый раз возвращает **новую копию** массива. В горячем коде — закешировать в `private static final` поле или `List.of(values())`.

## == и equals
- `==` корректен, потому что экземпляр один. `Enum.equals` тоже сравнивает ссылки — по результату то же самое.
- Преимущества `==`: `color == null` не бросит NPE, а `color == Size.LARGE` для чужого enum не скомпилируется. `color.equals(Size.LARGE)` скомпилируется и молча вернёт `false`.
- `switch` по `null`-enum без `case null` бросает NPE; `case null` в `switch` — с Java 21.

## Хранение и внешний ввод
- JPA по умолчанию пишет `ORDINAL`. Вставили константу в середину — старые строки молча читаются как другие значения. Нужен `@Enumerated(EnumType.STRING)` или явный код с конвертером.
- `STRING` тоже хрупок: переименование константы ломает старые данные. Стабильнее всего явное поле-код.
- `valueOf("active")` при константе `ACTIVE` — `IllegalArgumentException: No enum constant …`, а не `null`.
- Для данных партнёра или запроса — статическая `Map<String, Status>` (или поиск по коду) с `Optional` или явной веткой «неизвестно». Иначе новое значение у партнёра даёт 500.

## Тела констант
```java
enum Op {
    PLUS  { int apply(int a, int b) { return a + b; } },
    TIMES { int apply(int a, int b) { return a * b; } };
    abstract int apply(int a, int b);
}
```
- «Стратегия на константу» без `switch`: новая константа без `apply` не скомпилируется.
- `Op.PLUS.getClass()` — `Op$1`, и `isEnum()` у него `false`. Для карт по классу, логов и сериализации — `getDeclaringClass()`.

## Синглтон
- Сериализация по имени: десериализация вернёт ту же константу, `readResolve` не нужен.
- Создание потокобезопасно — его делает инициализация класса.
- Минусы: нельзя унаследоваться от класса, создание при первом обращении к enum без тонкой ленивости, плохо подменяется в тестах. В Spring синглтон — бин контекста.

## EnumMap и EnumSet
- Внутри `EnumMap` — массив по `ordinal`, `EnumSet` — битовая маска (в OpenJDK до 64 констант — один `long`). Быстрее и компактнее `HashMap`/`HashSet`.
- Обход — в порядке объявления констант.
- `null`-ключ в `EnumMap` и `null` в `EnumSet` — NPE. Не потокобезопасны.
- Фабрики: `EnumSet.of`, `noneOf(X.class)`, `allOf`, `range(from, to)` (включительно), `complementOf`.
